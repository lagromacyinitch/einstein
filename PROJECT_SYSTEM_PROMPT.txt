2. DATABASE SCHEMA (MySQL - einstein_db)
================================================================================

CREATE DATABASE einstein_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

TABLE: users
  - id (INT AUTO_INCREMENT PRIMARY KEY)
  - email (VARCHAR(255) UNIQUE NOT NULL)
  - password_hash (VARCHAR(255) NOT NULL)
  - is_verified (BOOLEAN DEFAULT 0)
  - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
  - updated_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)
  - INDEX idx_email (email)

TABLE: otp_codes
  - id (INT AUTO_INCREMENT PRIMARY KEY)
  - email (VARCHAR(255) NOT NULL)
  - otp_code (VARCHAR(6) NOT NULL)
  - expires_at (TIMESTAMP NOT NULL)
  - attempts (INT DEFAULT 0)
  - is_used (BOOLEAN DEFAULT 0)
  - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
  - INDEX idx_email_used (email, is_used)

TABLE: enrollments
  - id (INT AUTO_INCREMENT PRIMARY KEY)
  - reference_no (VARCHAR(50) UNIQUE NOT NULL)
  - user_id (INT NOT NULL, FOREIGN KEY REFERENCES users(id))
  - program (VARCHAR(100))
  - package_selected (VARCHAR(100))
  - start_date (DATE)
  - timeslot (VARCHAR(50))
  - child_name (VARCHAR(255))
  - child_age (INT)
  - child_grade (VARCHAR(100))
  - child_school (VARCHAR(255))
  - guardian_name (VARCHAR(255))
  - address (TEXT)
  - contact (VARCHAR(20))
  - facebook_name (VARCHAR(255))
  - payment_screenshot (VARCHAR(255))
  - payment_status (ENUM('pending', 'confirmed', 'failed') DEFAULT 'pending')
  - status (ENUM('draft', 'submitted', 'approved', 'rejected') DEFAULT 'draft')
  - admin_notes (TEXT)
  - created_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP)
  - updated_at (TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP)

4. ENROLLMENT FLOW - 6 STEP PROCESS
================================================================================

STEP 1: ACCOUNT AUTHENTICATION
  - Two tabs: "New Account" | "Existing Account"
  - NEW: Register email + password → auto-generate OTP → send to email
  - EXISTING: Login email + password → skip OTP → go to Step 3
  - POST: register.php or login.php
  - Returns: Boolean success/error with message

STEP 2: OTP VERIFICATION (New users only)
  - Email receives OTP code (6 digits)
  - User enters OTP in modal
  - POST: api_otp.php
  - Validates against otp_codes table
  - Max 3 attempts, 10-minute expiration
  - Returns: success → proceed to Step 3

STEP 3: ENROLLMENT FORM
  - Required fields: child name, age, grade, school, guardian name, address, contact, Facebook, program, timeslot, date
  - Form validation on client-side (enrollment-flow.js)
  - Stores in formData object

STEP 4: REVIEW & PAYMENT
  - Display form summary
  - Show pricing
  - Upload payment screenshot (FormData)
  - Payment status set to 'pending' initially

STEP 5: PROCESSING
  - POST: save_enrollment.php
  - Saves enrollment record to database
  - Assigns reference_no
  - Updates payment_status
  - Shows loading animation

STEP 6: SUCCESS
  - Display reference number
  - Confirmation message
  - Option to close modal

5. KEY JAVASCRIPT FUNCTIONS (enrollment-flow.js)
================================================================================

window.openEnrollmentFlow()
  - Opens enrollment modal from any page
  - Triggered by "Enroll Now" buttons

window.switchAuthMode(mode)
  - Switch between "new" and "login" tabs on Step 1
  - Tab visibility toggle

window.efStep1New()
  - Register: POST email/password to register.php
  - Response contains: success, message, otp_email
  - Auto-advances to Step 2 if successful

window.efStep1Login()
  - Login: POST email/password to login.php
  - Skips OTP, advances directly to Step 3

window.efStep2()
  - Verify OTP code user entered
  - POST to api_otp.php
  - Advances to Step 3 on success

window.efStep3()
  - Validate all form fields present
  - Stores values in formData object
  - Advances to Step 4

window.efStep4()
  - Capture payment screenshot via file input
  - FormData upload to save_enrollment.php
  - Advances to Step 5

window.post(url, data)
  - Async fetch wrapper
  - Uses URLSearchParams for POST
  - Returns JSON response

State Objects:
  - formData: { program, package, startDate, timeslot, childName, childAge, childGrade, childSchool, guardianName, address, contact, facebook, paymentScreenshot }
  - account: { email, password, isNewAccount }
  - debugOtp: { enabled, autoFill } (for development)

6. PHP BACKEND ENDPOINTS
================================================================================

register.php
  - Method: POST
  - Params: email, password
  - Process: Hash password, create users record, generate OTP, send email
  - Response: { success: bool, message: string, otp_email: string }

login.php
  - Method: POST
  - Params: email, password
  - Process: Verify credentials, start session
  - Response: { success: bool, message: string, user_id: int }

api_otp.php
  - Method: POST
  - Params: email, otp_code
  - Process: Validate OTP against otp_codes table, mark is_used=1, update is_verified in users
  - Response: { success: bool, message: string }

verify_account.php
  - Method: GET (email link)
  - Params: token (or email verification link)
  - Process: Mark user as verified
  - Response: Redirect or confirmation page

save_enrollment.php
  - Method: POST (multipart/form-data for file upload)
  - Params: All enrollment form fields + payment screenshot file
  - Process: Generate reference_no, insert into enrollments table, handle file upload
  - Response: { success: bool, reference_no: string, message: string }
